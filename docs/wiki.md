# Droid Wiki

The folder [`droid-wiki/`](../droid-wiki/overview/index.md) is a wiki of this codebase, generated by Factory Droid (`/wiki`). **Never hand-edit it.** Changes are overwritten by the next refresh. Fix the code or the docs instead, and let the wiki catch up.

## Daily refresh

[`.github/workflows/droid-wiki-refresh.yml`](../.github/workflows/droid-wiki-refresh.yml) refreshes the wiki:

- once a day at 17:00 UTC (about 03:00 AEST), and
- on manual dispatch (`gh workflow run droid-wiki-refresh.yml`). Add `-f force=true` to refresh even when nothing changed.

It does not run on push. A first `check` job compares the head of the last successful run with `HEAD` (`git log <sha>..HEAD -- . ':!droid-wiki'`). The refresh runs only when main changed outside `droid-wiki/`, when there is no previous successful run, or when `force=true`. Otherwise the later jobs are skipped.

When it runs:

1. `wiki-refresh` restores the previous wiki from the `factory/droid-wiki` branch (or from main), runs `droid exec --auto high "/wiki"` with read-only permissions, and uploads the result.
2. `wiki-publish` opens or updates a pull request from `factory/droid-wiki` titled `docs: refresh wiki`, labelled `droid-wiki`, and merges it automatically (squash, branch kept). If the push, pull request or merge is rejected, the run ends with a warning annotation instead of failing.

### Branch protection and the wiki pull request

Branch protection on `main` requires the CI jobs `Linux` and `Windows`. CI ignores `droid-wiki/**` (`paths-ignore` in `ci.yml`) and a pull request opened with the built-in `GITHUB_TOKEN` triggers no workflow, so those checks would never report and auto-merge would wait forever. After opening the pull request, `wiki-publish` therefore posts a `success` commit status named `Linux` and `Windows` on its head commit (the `REQUIRED_CHECKS` variable of the workflow). That is safe because the pull request only adds `droid-wiki/**`, which no check covers. If you rename a CI job or change the required checks, change `REQUIRED_CHECKS` as well. The repository setting `allow_auto_merge` must be on; `enforce_admins` is off, force pushes and deletions are blocked.

`droid-wiki/video/` and `droid-wiki/images/` are never committed.

## Secrets and settings

| Name                    | Required | Purpose                                                                                                                                                                                                                                                     |
| ----------------------- | -------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FACTORY_API_KEY`       | yes      | Repository secret that lets `droid exec` run `/wiki`.                                                                                                                                                                                                       |
| `FACTORY_WIKI_PR_TOKEN` | no       | Fine-grained token with `contents: write` and `pull-requests: write` on this repository. Use it when the wiki pull request must trigger other workflows (required checks). Pull requests created with the built-in `GITHUB_TOKEN` do not trigger workflows. |

Under Settings, Actions, General, "Allow GitHub Actions to create and approve pull requests" must be on (and "Allow auto-merge" if main has required checks).

Only secret names appear here and in the workflow. Never commit their values.
